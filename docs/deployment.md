# Deployment guide

ReviewLens needs a Next.js server runtime and a Supabase project. Do not deploy the authenticated application as a static GitHub Pages site.

## 1. Prepare Supabase

1. Create a Supabase project and save its URL, anon key, and project reference.
2. From the repository, run `npx supabase login`, `npx supabase link --project-ref YOUR_PROJECT_REF`, then `npx supabase db push`; alternatively apply both migrations in the Supabase SQL Editor.
3. Confirm `reviewlens-private` exists under Storage and its Public setting is off. The migration sets the bucket cap to 100 MB and adds user-folder ownership policies. The Supabase project-wide Storage limit must also be at least 100 MB; Supabase Free projects currently cap individual files at 50 MB, so 100 MB uploads require a plan with a higher limit and a project-wide limit change.
4. Under **Authentication → URL Configuration**, set the production Site URL to your final app origin, for example `https://reviewlens.example.com`.
5. Add `https://reviewlens.example.com/auth/callback` to the redirect URL allowlist. Keep the local callback URL for development if needed.
6. Configure an email provider/SMTP for confirmation and reset emails. If you disable email confirmation for a presentation, document that change and restore suitable controls for production use.

## 2. Deploy the Next.js application to Vercel

1. Push this repository to GitHub and import it into Vercel, or connect an existing Git deployment.
2. Keep the detected Next.js build command (`npm run build`) and output configuration. The build uses Webpack with compiler workers limited for reliable builds on constrained Windows hosts. Use the lockfile generated by `npm install` for reproducible dependency resolution.
3. Set these environment variables for Production and Preview as appropriate:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. Redeploy after environment changes.
5. Update Supabase Auth Site URL and callback allowlist to match the deployed origin exactly.
6. Open the deployment and verify registration/sign-in, an authenticated route, sample creation, CSV import, filtered review search, analysis history, all four exports, and private original-file download.
7. Run `npm run build` locally before release and inspect the Vercel deployment logs for build errors.

## 3. Production checklist

- [ ] `.env.local` and all real secrets remain out of Git; only `.env.example` is committed.
- [ ] `npm ci`, lint, typecheck, unit tests, and production build pass.
- [ ] Migrations are applied to the intended Supabase project.
- [ ] RLS is enabled for every application table and the migration policies are present.
- [ ] Storage bucket is private, size-limited, and protected by owner-folder policies.
- [ ] Supabase Site URL and callback URLs match local, preview, and production origins intentionally.
- [ ] SMTP or confirmation settings match the planned account workflow.
- [ ] Production logs, backup, retention, and privacy notice are appropriate for the data being processed.
- [ ] No service-role key or database password is exposed to the browser.
- [ ] No claim of regulatory compliance or certification is made without a separate assessment.

Vercel and Supabase dashboard labels may change; use each provider's current project settings if a menu label differs.
